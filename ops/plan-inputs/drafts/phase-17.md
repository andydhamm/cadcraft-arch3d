# Phase 17 plan: Stairs, decks, railings and openings in detail

Phase 17, Stairs, decks, railings and openings in detail, in 13 packages. p17-observables goes first with no deps (every new data field with its default, arch.inspect reporting them incl. railing posts and the glass plane, the phase-17 check lib and the carry-forward hostile and layers/wasm/i18n checks). Then two parallel infrastructure packages: p17-scene-plumbing (arch helpers for flights, deck edges and railing surfaces, the arch3d solid kit, part names and owners for every new material, incremental inputs and stub builders; it also waits for p16-scene-plumbing, which edits the same incremental.rs first) and p17-commands (every new param, stair.edit and deck.edit, the auto-railing and window-top hooks). Then the feature packages, each filling only its own stubs: p17-stair-flight (carry-over + stair parts), p17-wall-under-flight (after it), p17-stair-plan, p17-railing-parts, p17-railing-auto (after railing-parts), p17-deck-frame, p17-grilles-doors, p17-window-tops (after grilles-doors: same function). Last p17-exports-rebuild and p17-demo. Checks 01-14 under tests/acceptance/phase-17, plus phase-5 checks 03 (rewritten) and 07 (updated). Revision 2 (review): deck boards bounded to |deg| <= 360; roof-top windows keep a valid height through move, fit and stretch (check_height, validate_top); existing tests that later packages break are each owned and run by the package that breaks them (engine stair, p16_plumbing, golden_stairs, pick, lib.rs); the plumbing golden no longer pins a scene the feature packages change; the 3D pane's picking learns the new part names. Revision 3 (review): the deck boards show the Wood board texture (render3d, GLB, OBJ), so their direction is visible; each stair, railing and deck-structure kind is ONE GLB node and OBJ group (shares_a_node); shaped and roof window tops are built and validated from the wall's bottom (v0 = sill), so they sit right on upper-level walls; the showcase script's stairs are checked read-only on arch3d (they need no edit), while the demo keeps its own house and reports the showcase demo as not done (phase 15's showcase is still being built by the swarm).

Brief vs code, decided here (the code wins on facts):
(1) Nosing: the brief's own arithmetic (0.16875 + 2.025 x 0.16875 / 0.254) puts each tread's nosing 25 mm in front of its riser face, so tread 1's nosing (the first plan nosing line) is 25 mm before `start`; `start` stays where the STAIR command, the well and phase-5 check 04 put it (the first riser face's centre). Only the 3D flight and plan linework were one-sided (arch::stair::flight_polygon/well_polygon were already centred).
(2) The plan cut height is stored per stair (Stair.plan_cut, param planCut, default 1.2): levels have no plan settings and phase 16 edits level.rs tonight.
(3) Railing.post_spacing: Railing::default() goes 1.2 -> 1.8; the field was always serialised, so railings saved before keep 1.2.
(4) Sill and casing sides default to today's single side (the wall's right side, opening_meshes' -t/2 offset: the exterior of a counter-clockwise ring), so goldens and old drawings are unchanged; the window/door commands still default the casing WIDTH to 0 (a casing exists only with `casing` > 0).
(5) Part "post" is shared by railing posts and deck posts (and "footing" by phase 16's footings and deck piers): ownership goes by material prefix ("deck-" -> the deck room) in object_key, mesh_label, pick_part and arch_kind; build3d parts.post counts both, so deck checks read deck posts from arch.inspect {"decks": true}.
(6) GLB: one node per stair (stair-s<n>), per railing (railing-ra<n>) and per deck-structure kind (deck-r<n>-joists, -rims, -ledger, -beams, -posts, -piers): glb.rs shares_a_node accepts "stair-*", "railing-*" and the six deck-structure materials (p17-scene-plumbing), each part mesh a primitive of that node, and obj.rs groups the same meshes, because phase-12 check 01 requires the OBJ groups to equal the GLB mesh nodes. The bare legacy "stair"/"railing" keep a node per mesh as today (a stair writes two stair-s<n> nodes today; phase-12 check 06 unions same-named nodes); the boards stay deck-r<n>. IFC writes one IfcMember/IfcColumn/IfcFooting per member mesh.
(7) Automatic stair railings run from the first riser line to the top riser, inset 0.045 into the flight, 0.914 high (inside the 0.864..0.965 handrail band); deck railings follow the free edges inset 0.045, ends against a wall pulled back 0.045. Phase-5 check 07 selects the well guard by host "well".
(8) No opening.edit command exists; openings get their phase-17 details when placed. stair.edit and deck.edit are new (per-side rail settings need an edit path).
(9) Roof-top windows: windows only, in a wall with a roof top polyline (gable), refused otherwise; their height is derived; every placement check of a roof-top window (place_opening incl. its fit retries, arch.opening.move, arch.wall.stretch) uses arch::opening::check_height, which skips the wall-height head check for them; place and move re-derive the height through the engine's validate_top (p17-commands makes it, p17-window-tops calls it from the move), which measures from the wall's bottom on every level (outline bottom v0 = o.sill, the roof polyline from wall_span's base); a roof re-pitch leaves the stored height until the window is placed or moved again, while the 3D top always follows the roof; they get no header.
(10) Observed, not fixed (out of scope): walls::opening_holes places a rough hole at sill - base (base zeroed only for spanning walls), so a window on a single-level upper wall (base 2.7) does not cut its wall. Phase 17 does not widen it: opening_holes passes that same legacy v0 to rough_outline for every top (square holes stay byte-identical), while the shaped frames, glass, casings and the derived roof-top height use v0 = o.sill on the span base, as today's square frames (base + sill) and glass_plane do. p17-demo keeps its windows on level 1, has no roof-top window (its gables are on Level 2) and reports what it finds.
